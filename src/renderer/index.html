    OpenCode

    OpenCodeはここだけで接続先とモデルを一緒に保存します。切替前にタスクを停止し、OpenCodeのエージェント端末を終了してください。選択だけでは実行設定は変わりません。

    接続先を選び、OpenCodeログイン管理でそのサービスのAPIキーを登録してください。選択だけでは保存されません。「OpenCodeに適用」で切り替えます。

    OpenCodeの接続先は一度に1サービスです。接続先ごとの前回モデルと認証は保持します。同時にZ.AIとOllamaを別担当として使う構成には未対応です。SSH先では、そのマシンにもOpenCodeと認証が必要です。

    利用するAI・既定モデル・切替目安はまとめて保存します。OpenCodeの接続先変更だけは、下の「OpenCodeに適用」で確定します。

    モデル・認証・使用量について

    モデルの優先順：担当別 → タスク別 → Resourcesの設定 → CLI既定。候補はこのMacのCLIから取得します。契約内での利用を保証するものではありません。

    ログイン管理はこのMacの認証を確認します。OpenCodeは保存済み接続先が対象です。変更前の接続先の認証は「選択中の接続先のログインを確認」を使います。SSH先の認証は別です。

    使用量はどこから取得する？

    Codex・ClaudeはCLI認証、Antigravityは公式CLIのUsage連携、Ollamaは専用Webログインを使います。CLIへのログインと使用量取得の成功は別です。残量・観測時刻・エラーは右サイドバーとResourcesで確認できます。

    Antigravityは未設定のときだけ、ログイン管理画面に「使用量表示を設定」が表示されます。最新値はCLIの /usage で取得し、「状態を更新」で記録済みの値を読み直します。SSH先の認証・使用量とは別です。

    遠隔システム（SSH）接続先・作業フォルダ・システムの利用手順

    遠隔システム（SSH）

    CLIは選択した遠隔マシンで動作します。追加SSHには「手動で接続を準備」を使います。最終マシンにNode.js 18以上、各CLIとLLMへの外部通信許可が必要です。tmuxがあればCLIを保持し、SSH切断後も同じ工程へ再接続できます。再認証は手動です。施設の常駐・ログインノード利用規則を確認してください。

    接続用ターミナルで追加SSH・認証・環境設定・cdを済ませ、「ここを作業環境として確定」を押します。Node.js・Python 3・CLIが必要なのは最終マシンだけです。確定後は接続を連携専用に使い、CLIはタスク内の別ターミナルで操作します。

    新規登録はbwrapを使わないFull accessが標準です。既存設定は保持します。今後作るタスクに適用し、既存タスクは「遠隔Codexの権限…」から承認前でも個別に変更できます。Full accessでは承認要求と隔離保護がなく、読み取り担当も作業フォルダ外へ書き込めます。保存時に確認します。他のCLI・ローカル実行は変更しません。

    IPアドレスを直接入力できます。SSH configへの登録は不要です。登録済みのHost名も使えます。ユーザ名が空欄の場合はSSH設定、指定がなければMacのユーザ名を使います。

    ゴール・作業フォルダ・ログインユーザ・権限・成果・履歴は保持します。実行中は一時停止してください。保持中の遠隔CLIは新しいIPへ再接続後に確認し、確認前に別の担当は起動しません。

    projects/test → ログイン先のホーム/projects/test。認証後の「環境確認」で、なければ新しく作成します。空欄は ~/agent-harness。既存の共有領域などは /work/project のような絶対パスでも指定できます。

    詳細設定（通常は変更不要）

    Nodeは「計算ノード」ではなく、連携用プログラムを動かすNode.jsです。遠隔側にNode.js 18以上が必要です。通常は node のままにし、別の場所にある場合だけ /path/to/node を指定します。

    遠隔TeXコマンドは、この接続先でレポートを生成する場合に使用します。Macで生成する場合は「TeX・PDF・作図環境」のコマンドを使います。

    手順は接続先ごとの .txt に保存します。パスワード・秘密鍵・アクセストークンは記載しないでください。既存タスクは作成時の手順を保持します。

    レポート執筆ルール

    全媒体に「共通ルール」「表現・文体」「数値・文献の検証」と、該当する媒体のルールを適用します。AIらしい表現を避ける指示と既存の言い換え例は「表現・文体」にまとめました。各項目をクリックして編集できます。

    保存した変更は、次に開始する執筆担当・レポーターから適用されます。実行中の指示や完成済み文書は変更しません。過去の版を指定した担当・独立レビューは、その固定版を使います。読むだけの相談・レビューでは文書を変更しません。

    各欄はそれぞれ1つのルールです。保存・再読み込み・同梱ルールへの復元は、操作した欄だけに適用され、他の欄の未保存入力は保持します。

    共通ルール

    操作権限と安全性（説明）自動承認の対象・注意事項。設定を変更する欄ではありません

    CLIの操作権限

    Antigravity CLIはタスク実行時に操作承認を省略します（dangerously-skip-permissions）。Claude Codeも操作承認を省略します（bypassPermissions）。ローカル・遠隔ともファイル変更やコマンド実行が確認なしで行われます。読み取り担当の制限は指示によるもので、OSのサンドボックスではありません。専用の作業環境を推奨します。ログイン管理では自動承認しません。

    両CLIの起動時のフォルダ信頼確認は、指定した起動フォルダと表示パスが完全に一致する場合のみ自動承認します。長いパスは端末を一時的に広げて再確認し、確認後は元のサイズに戻します。フォルダ内の設定やフックも信頼対象となります。ホームを指定した場合はホーム全体が対象です。Codexは起動フォルダだけを信頼済みとして指定します。CLIの共有設定・認証ファイルを直接書き換えません。

    別フォルダ・未対応形式の確認、ログイン、組織側の制限には自動回答しません。手動でキーを入力すると、その起動での自動承認を停止します。起動済みのCLIには遡及しません。

    モード別の進め方各モード固有の目的・計画・作業・検証・報告内容

    通常は変更不要です。タスク作成時にモードを選ぶだけで、その進め方が適用されます。個別の成果物・達成条件は、タスクのゴールで指定します。

    変更が必要な場合だけ編集してください。保存後に作るタスクから適用され、既存タスクは変わりません。共通の原則や文章表現は、左の専用タブで設定します。

    レートリミット・使用枠

    使用率・残量・リセット日時を確認できます。「更新」で状態も確認します。使用枠は契約アカウントに紐づきますが、ログイン先が異なる可能性があるため取得元ごとに表示し、合算しません。

    全サービス共通の目安です。契約上限を100％として、この割合に達したら別サービスへの割当てを優先します。実行中の工程を強制終了せず、厳密な使用上限を保証するものではありません。

    各サービスの「利用する」の下で、契約上限の何％まで使うかを指定します。セッション・週など、選択モデルに関係する取得済みの使用率で判断します。使用率が未取得なら判定できず、トークン数からは推測しません。同じ契約を複数CLIで共有する場合は低い目安を採用します。

    目安に達したら別サービスへの割当てを優先します。実行中の作業は強制終了しません。代替がない場合や担当を固定した場合は超えることがあるため、厳密な使用制限ではありません。保存時に旧トークン数指定を置き換えます。

    作業開始前のSSH認証

    下の端末でSSHのパスワード・多要素認証・初回ホスト鍵確認を行ってください。パスワードは通常、入力しても表示されません。アプリの設定には保存しません。

    認証後に「環境確認して続行」を押してください。接続済みの場合は再入力不要です。フォルダがなければ作成し、その後にCLIを起動します。
