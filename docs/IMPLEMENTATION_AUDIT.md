## 再現して修正した不具合

- **設定の同時保存**：複数の保存処理が同じ一時ファイルを書き換え、renameがENOENTで失敗した。レポート設定と割当設定の同時更新を含むテストで再現。
- **使用量の同時保存**：複数サービスの更新でも同じ競合が発生した。通常の並列Refreshでも到達する経路なので、Refresh失敗の原因になり得る。サービス別の結果がすべて再読込できることを確認。
- **低い使用率の誤変換**：`usedPercent: 0.5`など、単位が百分率の値を50%へ変換していた。百分率フィールドと従来の比率形式を区別した。専用のCodex/Claude使用量取得処理を変更したものではない。
- **使用量の取得時刻**：クールダウン終了時に、過去の観測値の取得時刻を現在時刻へ更新していた。実際に新しい観測を得た場合だけ取得時刻を更新する。
- **割当設定の不正数値**：NaNなどが閾値チェックを通り、保存時にnullになるケースを拒否する。優先度・予算にも有限数チェックを追加。
- **画面履歴の閲覧位置**：タスク情報の更新で履歴ペインが再構築されると最新画面へ戻った。画面選択・ページ・スクロール位置を実行ごとに保持する。古いページを表示中のクリアも、すでに記録された新しいページまで表示対象から除外する。外部ログは消さない。
