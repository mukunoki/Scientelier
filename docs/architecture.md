# コードを読むための案内

## 名称と互換性

公開名称・リポジトリはScientelier。既存の設定と暗号化されたキーを読めるよう、Electronの内部名とuserDataのagent-harness、bundle identifier、MCPのagent_harnessは維持する。画面・Macメニュー・Aboutの名称は別に指定する。内部名をブランド名へ一括置換しない。開発用ランチャーは外部ソースを読み、単独起動配布版は内部に実行コード・skills・本番依存を保持する。両方とも実mainモジュールに基づくprojectRootから取得する。個人データはruntime-paths.tsでソース外へ分離し、既存保存先を保つ。

## 公開・インストールの境界

`scripts/release-files.cjs` は公開ソースの許可リスト、通常ファイル検査、機密形式検査を共有する。`export-public-source.cjs` はGit追跡ファイルから履歴なしの新しいソースディレクトリを作る。`package-mac-app.cjs` はそのリストと追跡ソースに対応するコンパイル済みJSから配布アプリを作り、本番依存だけを同梱する。古いdistのテストや未追跡実験をglobで取り込まない。元の履歴・private公開設定は変更しない。

IPSJ原配布はprivate互換用の既存資産で、公開許可リストに入れない。`install-ipsj.cjs` が公式URL・固定SHA-256・選択エントリで個人領域へ取得する。`ReportService` の文書テンプレートとIPSJスタイルの場所は独立し、公開版でIPSJ未取得でもBeamerを参照できる。更新でユーザー編集ルールや成果物を削除しない。

## 責務の分担

品質・速度を中心とした主担当方式では、`primary-owner.ts` が保存済み主担当の継続と明示的な担当指定をまとめる。`orchestration.ts` は使用枠・認証・独立性を満たす候補から能力参考と品質優先値で主担当を選ぶ。他の作業は従来の使用枠・負荷分散を使う。能力データのないモデルを低能力と決めず、CLIと実モデルの同一性も混同しない。

新規研究の `integratedWorkflow` は、保存した四モードのルールを一人の主担当の方法として配布する。固定 `researchStage` 列は作らず、既存の実行計画・分離作業・統合・仕上げ・独立レビューを再利用する。旧スナップショットの工程は保持する。`primaryDocument:paper` は主レポートを論文とし、別の文書ターゲットを作らない。旧 `document:paper` の二文書互換経路は削除しない。

総tokensの目標は旧データを読むために残すが、起動・計画・統括判断の着手制御には使わない。実際のサービス使用枠、計画版数、修復回数、並列上限、権限・共有資源の排他は独立した制約である。`substantive-report.ts` の任意 `workReport` は提案・作業・結果・解釈を表示するためだけの情報であり、合格・権限・証拠を代替しない。不正・欠落は従来の要約表示に戻し、新たな提出ループを発生させない。

遠隔端末の保持は `tmux-session.ts`、短い担当間の相談は `agent-messages.ts` へ分離する。tmuxはCLIの画面・プロセス保持だけを担当し、計画・使用枠・工程完了・引継ぎは既存ハーネスが管理する。tmuxの生存や相談の回答を成功・承認の証明にしない。

遠隔は最終マシンのtmuxを自動検出し、実行ごとの専用ソケット・トークン・ホスト照合で同じCLIへ再接続する。接続断・アプリ終了は端末から切り離すだけで、後続担当は起動しない。明示的な一時停止や他AIへの引継ぎは従来の終了通知・ロック解除確認を必須とする。保存した起動指示・スキル・実行IDを再接続で変更しない。通常のユーザーのtmuxサーバーには触れず、終了確認後は所有セッションだけ片付ける。

相談はMCPのsend_message/read_messages（非MCP CLIは同じヘルパー）へ提出し、既存のファイル転送接続で中継する。新しいSSH接続やCLIは作らない。主担当と分担担当、計画で指定された担当間だけが対象で、独立レビュー・独立案・反証担当は除外する。相談は担当12通・1論点2往復・1500文字以内。受信文は未検証データであり、権限・指示・証拠を上書きしない。ラウンド・ゴール版・計画版・担当IDを照合し、旧相談は履歴として残す。履歴表示はtextContentだけを用いる。

## 変更時に守ること

- **履歴と現在利用できるCLIを区別する。** Geminiの識別子は過去のタスクを読むために残すが、新しい起動・ログインの選択肢には含めない。
- **保存済み値と未保存の編集は別。** 設定保存の送信後にも入力できる。応答で再描画する前に編集版を比較し、その後の入力を消さない。
- **OpenCodeのモデルは接続先とセット。** 共通のモデル保存で接続先専用のモデルを上書きしない。Z.AIとOllamaは同じOpenCode APIを通す。
- **接続先の適用でサービスの利用可否を変えない。** OpenCodeをOFFにした場合、モデル・接続先を保存してもOFFを維持する。
- **設定の結果・エラーを折りたたみ内へ隠さない。** 遠隔設定の保存メッセージは接続操作を展開しなくても読める位置に残す。
- **古い端末の応答を捨てる。** 非同期の画面取得後に端末IDを再確認し、終了・再接続済みなら結果もエラーも反映しない。
- **非同期処理の前に読んだタスクは古くなる。** 並列担当の結果を反映するときは最新状態を使い、`updateTaskRecord`のタスク別更新列を維持する。
- **停止と失敗と完了を混同しない。** キューの停止は新しいタスクの入場を止める操作。工程の完了は終了コードだけでなく提出結果と証拠で判定する。
- **品質検査と独立レビューを混同しない。** 品質結果はファイル指紋・計画版・承認要件・依存結果で再検証する。スクリプト自己申告だけでは真実性を保証しない。文書だけの不備はレポーターへ、実装・データ不足はワーカーへ戻す。
- **時間の監視で新しい管理ループを増やさない。** 1/3・2/3の中間判断は既存の最大3回の枠で実行し、早期の完了イベントですべて使い切らない。tokens推定値は観測用。計測中は待ち、実行中・開始済み・独立確認の指示を変更しない。
- **再確認は意味のある変更で行う。** 同じ品質記録を再提出しても結果IDを変えない。`recheck`で実際に変わったファイル・検査方法・依存結果を示す。実験入力や達成条件の依存関係を省くことで検証を軽くしてはならない。
- **新しい必須条件を既存タスクに後付けしない。** `qualityCycle`のない保存済みタスクの経路を変えない。`quality.ts`を更新したらMCP単体転送テストと遠隔CLIフィクスチャも検証する。
- **UIの分類変更で入力要素を複製しない。** 既存ノードを移動し、イベント・入力値・IDを保持する。
- **設定の折りたたみは一階層。** 分類は通常の見出し、各編集項目だけをdetailsとする。動的に再描画する編集欄も `#settings-view details details` を作らない。
- **rendererはNode.jsを直接呼ばない。** `index.html`のdeferスクリプトから共有型と関数を利用する構成。実行時importを追加する場合はビルド方式も含めて検討する。

## 「未使用」に見えても残すコード

- 旧ログ表示はPTY導入前のタスクを読む互換経路。
- `writing-rules-update.ts`は明示的なルール移行用の補助処理。確認した版の照合とバックアップを行い、アプリ起動時には自動適用しない。
- `prepared-server.ts`などはSSH先へ転送するソース一覧から動的に読み込まれる。静的importだけの検索では参照を見落とす。
- ログインのエラー判定には過去のCLI名を含む文字列がある。これは起動経路ではなく、受信メッセージの分類。

## 検証

- `npm run build`：型・未使用の局所変数・引数を確認。
- `npm test`：工程、保存、キュー、レビュー、IPC公開契約などの回帰テスト。
- `npm run test:layout`：一時データでGUI・PTY・ルール編集・画面サイズ変更を確認。
- `npm run test:layout -- --models`：モデル保存、二重送信、保存中の追加入力、負荷分散の編集保持。
- `npm run test:layout -- --skills`：スキル登録・採用・保存版・保存中の追加入力・編集欄のサイズ変更。
- `npm run test:layout -- --antigravity-login`：認証端末の保持、入力、使用量表示。
- `npm run test:layout -- --ollama-app-only`：OpenCodeの接続先とモデル・認証の対応。
- `npm run test:layout -- --terminal-ui-only`：現行の依存グラフ、端末入力・終了後の入力抑止・サイズ追従と旧保存ログ。
- `npm run test:layout -- --report-location-only`：作業環境でのPDF生成方針と遠隔レポートの再開表示。

`dist`は生成物。ソースを削除・改名した際、TypeScriptは古い出力を自動削除しないため、該当する生成物だけを確認して除去する。特に古い `*.test.js` が残ると廃止した機能のテストが実行される。

## 今後の整理余地

スキルは実行時に必要なものだけ読み、確認用の指示書TXTでは全文を維持する。MCP対応CLIは `get_skill`、Antigravityは実行専用の `skills/<id>.md` を使う。SSH先にも同じ本文を転送する。取得記録は本文を含まない実行別の有界な追記ログで、ID・内容ハッシュ・UTF-8バイト数から呼出回数と本文の推定tokensを集計し、AgentRunへ保存する。記録失敗は実行を止めず、未観測を未使用とは断定しない。Antigravityのファイル読取は未観測なので、推定には提示した全本文を保守的に算入する。実トークン、キャッシュ課金、モデルの内部文脈を測定する仕組みではない。

`main.ts`の工程実行・IPC登録と`renderer/index.ts`のタスク表示はまだ大きい。今回の整理では実行中状態や互換性を優先し、全面的な分割や保存形式変更は行っていない。またrendererとcoreの型は一部重複している。型だけを共通化する場合も、ブラウザにNode依存を持ち込まないことと、GUI専用の表示項目の違いを確認する必要がある。
