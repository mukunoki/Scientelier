# 数値・文献の検証

[共通ルール](../de-ai-style/SKILL.md)と併用する。執筆前に検査と担当を計画し、変更後・最終ビルド後・独立レビューで確認する。数値・文献・関連研究を含まない文書に、検査のためだけのデータや引用を追加しない。

## 分担・判定・記録

- 主担当は検査の整備と独立照合を既存の工程へ割り当てる。計画専任・読み取り専用担当は作成・変更・副作用のある検査を行わず、必要な実行を許可された書き込み担当へ戻す。証跡のために読み取り専用制約を破らない。
- レポーターは自身の検査・組版確認と後続AIの独立確認を区別する。後続レビューの待機だけでレポーター工程を止めず、未実施分を引き継ぐ。欠けた実験・データはワーカーへ戻す。タスク全体の合格は必須検証が揃ってから判断する。
- pass/fail/unverified/not-applicableを区別する。対象ゼロ・解析失敗・未対応・読み飛ばしを合格にせず、対象なしの根拠または未確認の理由を記す。重要な不一致・未確認は既存のconcernsと該当条件のfail/unverifiedに残し、具体的な修正へ戻す。推測による補完、許容誤差の拡大、無断の除外で通さない。
- 管理記録は検証用ファイルまたは読み取り専用担当のレビュー結果に置く。対象箇所・ID／文献キー、入力／資料と版・ハッシュ等、方法／コマンド、使用AIとモデル、確認日、結果・相違点・未検証範囲を結ぶ。一次資料にはURL／DOIとページ・節・図表等の根拠箇所を付け、閲覧事実やページ番号を創作しない。本文・付録には管理記録ではなく、主題に必要な根拠・引用・留保を記す。

## 図表の説明と数値の提示

- 見出し・軸・凡例で対象、指標、単位、無次元の比を区別する。「上限／比／unit」だけの曖昧な列名を避ける。速度比は分子・分母と大小どちらが良いかを示す。理論値・推定値・計測値を区別し、同じ実験・構成・入力範囲・条件で比較する。
- キャプションに対象・条件・単位を示す。図の目的、色・線・閾値の意味と他図との対応を保ち、無関係な図やスクリプト全体へ変更を広げない。
- 図表は詳細な値と比較条件を担う。本文では図表の数値を順に読み上げず、図表の概略、主要な傾向・比較・例外と、そこから分かることを説明する。行・列・系列ごとの数値一覧を文章へ転記せず、結果が問い・仮説・提案の有効性や適用範囲にどう関係するかを書く。因果関係を確認していない場合、原因の説明は仮説として観測結果と区別する。考察のない数値列挙を「結果の説明」としない。日本語・英語の両方に適用する。
- 本文に再掲する数値は、主要な結論を支える代表値・重要な対比・判定閾値・不確実性等、議論に必要なものに絞り、対応する図表を参照する。数値を一切書かない規則や固定件数のノルマにはしない。正確な条件・精度・例外の理解に必要な数値は残し、都合の良い代表値だけを選んだり、重要な未達やばらつきを隠したりしない。
- 執筆・最終推敲・独立／敵対レビューでは、図表を参照する各段落について「セルや点の値を言い直すだけでなく、読者が理解すべき要点と解釈を伝えているか」を確認する。読み上げ中心なら概略・意味・比較の説明へ書き直す。数字を削るだけで済ませず、根拠のない説明で穴埋めしない。重複候補の機械抽出は補助とし、議論に必要な再掲を自動削除しない。スライド・ポスターでは同じ区別を短い要点で表す。

## 執筆前の検証スクリプト整備（必須）

- 論文・レポート・ポスター・スライドの大量の本文や図表を作る前に、機械検査と意味のレビューを分ける。既存ツールの再利用を優先し、必要なPython等の小さな検証スクリプトを、作成・検証・保守の費用に見合う範囲で整備する。不要な汎用基盤は作らない。
- 数値の一致：実験ID、条件、入力ファイル・列・行、集計式と、表セル・図の系列／点・本文・スライドの対応をJSON/CSV等に登録する。元の実験データから独立に集計し直す。丸め前データを正本とし、単位換算、丸め規則、有効桁、事前に決めた絶対／相対許容誤差を適用する。欠損・NaN・重複・条件違い・未対応セルも検出する。文書内の別の場所に同じ値があるだけでは一致にせず、期待値や原データを誤った掲載値に合わせない。
- 図表の再現性：元データから図表・数値マクロを生成し、手転記を減らす。生成と検査が同じ誤りを共有しないよう、既知の小例や別計算で検証する。入力系列・描画条件・生成物の版、古い画像、手編集、軸・単位・凡例・誤差棒を点検する。画像中の値が読めなければ未検証とし、目視等で補う。データ一致だけで実験の真正性を証明せず、取得条件・実行ログ・来歴も確認する。
- 用語辞書：正規表記、許容別名・日英表記、略語、明示的な定義箇所、前提用語、例外箇所と理由を登録する。表記揺れ、未展開の略語、定義前の使用、前提より先の説明を検査する。単なる初出を定義とみなさず、TeXのinclude等を含む実際の読順と、要旨・図注・引用・固有名詞・同形異義語を考慮する。意味上の警告はレビューへ渡し、機械的に置換しない。
- 参照と整合性：未定義参照・重複ラベル・未参照図表・未解決引用キー・欠落画像／データ、単位・百分率・速度向上率、本文と図表・要旨と結論・媒体間の不一致、再生成漏れから必要な検査を選び、対象外も記す。文献の初出順・一覧順は投稿様式が要求する場合だけ検査する。コメント・未使用ファイル・独自マクロ等の誤検知を分け、検索を打ち切って「該当なし」にしない。研究内容や開示の「agent／照合／再実行」等を機械的に削除しない。
- 検査自体のテスト：正常例だけでなく、値を変えた表・欠損・重複ID・定義前の用語等の小さな異常例で、誤りを検出できることを確かめる。実データを壊して試さない。対象件数・照合件数・除外・未検証と理由を出す。
- 再実行と再利用：データ・図表・用語・本文・検査コード／設定の変更後と最終ビルド後に影響する検査を再実行する。実際の転送物と生成物の版を照合し、古い合格結果を流用しない。スクリプトと設定はharness-skills/document-checks/等の既存の適切な場所にまとめ、索引・SKILL.mdから必要なものだけを読む。LLMには長い生データではなく要約・差分・エラー箇所・証跡パスを渡す。
- 独立・敵対レビューは検査コード・設定・検査漏れを点検し、重要な数値を元データから独立再計算する。最終PDF等にも検査対象が反映され、正しく表示されているか確認する。自動検査は独立レビュー・原論文照合・PDF目視を代替しない。

## 文献情報の一次ソース二重チェック（必須）

- 全引用文献の著者全員の氏名と順序、正式タイトル、掲載論文誌・会議／論文集の正式名称、巻・号、開始／終了ページまたは論文番号、記載するページ数、出版年・公開年、DOI等を照合する。プレプリント・採録版・正式出版版・オンライン先行公開を混同せず、引用した版を使う。
- 出版社・学会の公式掲載ページ、正式PDF、公式論文集・機関リポジトリ等の一次ソースを実際に開いて確認する。検索要約・第三者の一覧・生成BibTeX・AIの記憶だけで確定しない。架空のページ範囲を補わず、食い違いは版・刊行時期・訂正情報を調べて解決する。
- 異なる2種類のAI（実際に異なるモデル系統、異なる提供元を優先）による独立した全件照合を必須とする。CLI・担当・セッション名だけの違いを2種類と数えない。各AIは相手の判定を根拠にせず、一次資料の各項目を自ら照合してから突き合わせる。同じ正式一次資料を両者が確認してよい。1種類しか使えなければ代替の異種AIを手配し、それも不可能なら未確認とする。
- 各AIの項目別照合結果と根拠を上の管理記録に残し、不一致を解消する。引用・書誌情報を直した場合は変更文献を両AIで再確認する。レポーター単独で二重照合済みと宣言しない。
- 著者は一次資料の順序・確認できるフルネームで全員を記載し、et al.／ほか／他／and othersで省略しない。頭文字から推測して展開しない。正式資料でも氏名を確認できなければ未確認とし、団体著者は公式名称を使う。BibTeXだけでなく生成されたPDFの文献一覧・本文にも省略がないことを確認する。長い著者列はレイアウトで対応し、文字縮小・著者削除で収めない。必須の投稿様式と両立しなければ不一致を明示する。

## 関連研究の内容忠実性チェック（必須）

- 書誌情報が正しくても紹介内容が正しいとは限らない。本文・比較表・図注等で紹介した研究の主要な主張を全件対象とし、引用した版の原論文本文・図表・数式・実験設定・補足資料の該当箇所を読む。タイトル・要旨・検索要約・第三者の解説・AIの記憶だけで確定しない。
- 研究目的、提案手法の仕組み、仮定・範囲、実験条件、比較対象・指標・数値、結果・限界を照合する。他研究との取り違え、提案と実証、著者の主張と自分の推論の混同、限定的結果の一般化、条件違いの性能比較、重要な制約の省略を探し、原論文より強く断定しない。引用された別研究の成果をその著者の成果としない。
- 執筆時・修正後と、異なるAIの独立・敵対レビューで確認する。逐次レビューの各回・並列レビューの各担当・クロスレビューの再検証で原論文を自ら開き、前担当の合格や照合表で代用しない。反例・矛盾・省略された条件を探し、性能・優位性・新規性を特に精査する。
- 紹介文の箇所・文献キー・主張と、一次資料の根拠箇所・判定・相違点を対応づける。本文未取得・裏付け不足・過大な説明は未確認または不一致とし、承認範囲内で再取得・訂正・限定して再照合する。根拠不足のまま合格にしない。
