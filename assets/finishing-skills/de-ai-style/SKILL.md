# レポート執筆ルール — 共通

全媒体の執筆・追記・修正・仕上げに適用する。表現は[表現・文体](../report-writing-style/SKILL.md)、数値・文献・機械検査は[数値・文献の検証](../report-writing-verification/SKILL.md)、構成と組版は該当する媒体のルールを併用する。ハーネスから渡された固定版を正本とし、旧補足を重ねない。

## 内容と原稿の扱い

- 承認済みの目的・成果物・様式に沿い、TeXを主たる原稿として更新する。指定がなければ執筆テーマより一段階広い分野の読者を想定し、必要な前提知識を省かない。読者レベルの指定を優先する。
- 検証済みの結果と一次資料に基づいて書く。数値・単位・有効桁・数式・比較条件・否定・統計的意味・不確実性・限界・反証を保持する。相関を因果、予備評価を実証に変えず、実験・引用・経験談・効果量を創作しない。ゴール・合格基準・作業権限を無断で変えない。
- 実際に読み込まれる原稿・図表・文献と、著者が固定した文・用語を確認する。要約ではなく現物と前後の文脈を読み、旧稿を現行の欠陥としない。共有版はGit等で保持し、無関係な変更を混ぜない。
- TeXのエスケープ・マクロ・識別子・参照キーを保つ。実行ログ、エージェント名、工程、トークン量、推敲の経緯を本文・付録・TeXコメントに混ぜない。必要な技術コメント、研究内容としての記述、AI利用開示は保持する。

## 構成と説明順序

1. 全体の目的から節・段落・文・語句の順に整理し、構造を直してから語句を直す（二段階推敲）。「何が読みやすくなるか」を説明できない好みの変更はしない。
2. 背景・課題・目的から方法・結果・解釈・結論へ進める順序を設計する。用語・略語・記号は初めて使う箇所までに定義する。固有名詞には短い説明、略称にはフルスペルを添えるが、想定読者に一般的なCPU・GPU等は展開不要。
3. 必要な定義・前提を後の節に先送りし、「詳細は後述」で未説明の概念を使わない。その場で簡潔に説明するか、説明を前へ移す。図表・式・文献への通常の参照は維持する。
4. 前節で分かったことが次節の問いや方法につながるよう、節の役割と主張・根拠の対応を確認する。定型的な接続文を増やさず、内容のない重複だけを整理する。理解に必要な要約・対比・段階的説明は残す。「最良／最小／全数／証明／初めて」は成立範囲を明示する。
5. 主要な節がまとまった時点、結果・主張・構成を変更した時点、仕上げ時に文書全体を冒頭から通読する。説明順序、未定義語、節のつながり、読みやすさ、重複説明を点検し、移動・統合・書き直しを行う。局所的な追記だけで済ませない。接続語・指示語・図表参照を孤立させず、留保を適切な箇所に置く。

## 修正と完了確認

- 指摘は現物の根拠を確かめ、「採用／不採用／保留・理由・箇所」を管理結果に残す。意味が変わる提案は修正し、自然な箇所を無理に書き換えない。承認範囲内の通常の判断で毎回ユーザー確認を求めない。
- **変更箇所の再確認**：差分と指摘を照合し、前後の文・関連図表・既存の他言語版を読む。意味・断定・整合性を確認し、影響する検査を再実行する。
- **全文・生成物の最終確認**：本文・図注・注記・付録・ノートを通読する。最終編集後にPDF等を再生成し、その版の全ページを描画・目視して欠け・重なり・空白・はみ出し・文字サイズを点検する。変更箇所の確認や文字抽出だけで代用しない。PDFに含まれないノートもソース側で確認する。
- レポーターは既存のeditorial-checkに適用版・全対象ソース・変更と確認の概要・未解決事項を提出する。独立・敵対レビューは「箇所（行／PDFページ）・原文・問題と根拠・最小修正案・重要度」を返す。既存工程で行い、別CLIを直接起動しない。読み取り専用担当は編集せず、検証の分担と判定は検証ルールに従う。
