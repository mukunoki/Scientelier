# 自作スキルの採用試験

- 自作スキルの正本は現在の許可された作業フォルダ内のharness-skills/<name>/SKILL.mdとし、既存のharness-skills/INDEX.txtへ名前・用途・相対パス・版・status・検証証拠パスを記す。statusはexperimentalから始める。experimental/validated等の別ディレクトリへ移動・複製しない。索引は人とエージェントの発見用で、自動承認ではない。目的、発動条件、適用外、許可された副作用、版とテストケースを先に固定する。既存のスキルと重複するなら拡張を優先する。
- 正常例、検出すべき異常例、適用外の例を分け、観測可能な期待結果と実際の出力を照合する。検査文言や自己申告ではなく、成果物・エラー検出・書き込み先などの事実を評価する。
- 同じケース・環境・予算条件で既存手順と比べ、成功率、見落とし、誤警告、時間、取得できた場合の実測トークン消費を記録する。未取得をゼロとして扱わず、不確実な改善を節約実績として報告しない。
- 独立した担当がコード・テスト・副作用と適用範囲を点検する。読み取り専用担当は実行や保存を要する試験を作業担当へ戻す。試験対象に採点基準や期待出力を漏らして正解をハードコードさせない。
- 合格してもまず同じ作業フォルダ内のvalidatedとして再利用し、版・適用条件・証拠を索引へ記す。変更時は試験をやり直す。不具合はexperimentalまたはretiredへ戻し、過去の利用箇所への影響を調べる。
- 全タスク共通への昇格・グローバルCLI設定変更は自動で行わない。比較結果と変更差分を提案し、ユーザー承認を得てから既存ルールを保護して適用する。スキルの指示は権限を追加しない。
