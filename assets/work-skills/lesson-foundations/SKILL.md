# 背景からの論文理解

承認済みのlesson設定を正本にする。論文の難易度から読者の知識を決めつけない。既知は長い説明を省くが用語対応を示し、復習は短い確認、基礎からは初出の定義と具体例、詳しくは導出・条件・限界まで扱う。

- 原論文の各核心を理解するために必要な概念を逆算し、前提関係の循環を解消してから教材の説明順序に並べる。原論文の章順に縛られない。
- 最初に解けるようになる問いを示す。具体例→背景・前提→従来法→困る例→着想→仕組み→数式→実験の読み方→限界を、題材に応じて組み替える。
- 主張・数式・実験・限界を原文のページ/節/式/図と対応付ける。背景の補足には教科書・公式資料等の一次的資料を用い、対象論文の主張と補足を明示的に区別する。共通のrelated-research・文献照合規約は複製せず適用する。
- Git参考資料を読む場合、確認したコミットと対応ファイルを記録する。論文版とコード版の相違を隠さない。参考URLだけでコード実行・インストール・大規模実験を許可されたと解釈しない。
- 原文取得不能、スキャンの読取不良、版の不一致は具体的に残す。推測で補完しない。必要な一次資料の取得・独立照合は最終報告より前に計画する。
- 教材の各主要章で、読者が答えられるはずの問いと理由付き解答を用意する。答えの暗記だけで済まない小さな条件変更・反例も有用なら含める。

新しい前提不足を発見した場合、承認範囲内の補足ページで解消する。読者レベル・目的自体を変更する必要があれば変更案を提示する。管理ログ・役割名を教材に載せない。
