# 読むための紙芝居型Beamer

100ページ以上を許容する。ページ数は目標でも上限でもない。一枚進むと理解が一段進むことを重視し、予算不足を理由に未検証の教材を完成扱いしない。

## 絵コンテ

TeXのコメントに `% lesson-frame: stable-id` と、問い・必要な前提・図/具体例・結論・次との接続・原典箇所を置いてから制作する。IDは修正でページ番号が変わっても保つ。一枚の中心事項は一つにする。章の入口で問い、出口でわかったことと残る疑問を示す。

## 図と具体例

- 同じ図の配置・色・記号を後続ページでも維持し、追加/変化部分だけ強調する。色だけに意味を依存させない。矢印の意味、軸・単位、凡例を説明する。
- アルゴリズムは小さな入力を最初から最後まで追う。比較は条件・尺度・配置をそろえる。装飾的な図より、因果・対応・状態変化が見える図を選ぶ。
- 数式は「何を求めるか→各記号→数値例→途中計算→解釈→一般形」と段階化する。途中式を飛ばしていないか読者設定に照らす。
- 比喩には対応するものと対応しない点を添える。概念図は実測プロットではない。説明用データを実験結果と混同しない。
- TikZや既存の作図ツールで再生成可能な図を優先し、出典・元データを保持する。専門的な図は見た目だけで合格にしない。

## 自習PDF

16:9を初期値とし、文字を縮小して詰め込まずページを分ける。発表者の口頭説明・非表示ノートに依存しない。段階表示の全状態をPDFで読めるようにし、スキップした読者にも章と進行がわかる見出しを付ける。目次・しおり・章移動と詳細へのリンクを使う。共通の表現推敲は適用するが、発表時間への圧縮規則は適用しない。

## 検査

教材ディレクトリの同梱検査 `node check-lesson.cjs report.tex` をビルド後に実行する。フレームIDの重複・不足、参照切れ・はみ出し警告を検出する構造検査であり、意味・数値・出典・可読性の合格判定ではない。動的TeX構文は手動確認が必要になる。マクロでフレームを生成する場合も安定IDとの対応を保持し、検査を黙って省略しない。

document-checksとscript-reuseを利用して用語初出、参照、数値例の再計算、元データとの照合を必要に応じて自動化する。ビルド警告・未解決参照を確認し、PDFの全ページを表示して文字/図の可読性、はみ出し、段階表示、空白や重複を確認する。機械検査は意味の正しさを保証しない。修正した章の前後も見直し、最終版は通読する。
