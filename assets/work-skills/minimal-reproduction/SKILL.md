# 最小再現・原因切り分け

- 失敗した版・入力・環境・コマンド・期待結果・実際の結果を固定し、機密を伏せた再現条件を残す。修正前に再現できるか確認する。再現不能は未解決であり、修正成功としない。
- 既存データを保護した小さなケースへ絞り、原因候補を分ける検査を一つずつ行う。共有入力、基準結果、テストの期待値を誤った実装に合わせて変えない。
- コード、データ、実行環境、通信/認証、評価器のどこで失敗したかを区別する。認証や権限不足をコード変更・無限再試行で回避しない。副作用のある処理は再実行前に完了状態を調べ、二重投入を防ぐ。
- 書き込み可能な担当が最小修正と回帰テストを追加し、修正前は失敗、修正後は成功することと近接ケースを確認する。無関係なリファクタリングを混ぜない。
- 同じ仮説・操作の反復ではなく、新しい証拠が得られる次の検査を選ぶ。試行上限・ユーザー停止・担当所有範囲を守る。
- 引き継ぎは再現コマンド、原因を支持/否定した証拠、修正、回帰テスト、未解決事項のパス。レビュー担当は保存された証拠を点検し、必要な書き込み実行を担当へ戻す。
