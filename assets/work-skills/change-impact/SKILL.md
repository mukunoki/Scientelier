# 変更の影響範囲と再検証

- 必要な範囲だけ、入力→処理→中間データ→図表→原稿→PDF/スライド→検査の依存関係を現在の許可された作業フォルダのharness-skills/dependencies.jsonへ記録する。既存のビルド・検証台帳があればそれを正本として再利用し、harness-skills/INDEX.txtにパスだけ案内して重複作成しない。各項目にパス、ハッシュ等の版識別、生成コマンド、直接依存、検査結果と検査対象版を結ぶ。秘密情報は保存しない。
- 共有索引の更新は主担当に任せる。分離ワークツリー担当は許可された所有ファイルだけに記録し、レポーターは報告書フォルダ内に限定する。新しい保存先の指定は権限を広げない。
- 変更された入力・コード・設定から下流の成果物と合格記録を無効と判定し、必要な再生成・再検査を計画する。検査コードや許容差の変更も対象にする。時刻だけで内容一致を断定しない。
- 依存関係が不明、マクロや動的入力で追跡できない場合は未確認として、広い再検査または独立レビューを選ぶ。「差分が小さい」だけで検査を省略しない。
- 選択的な再検査を行っても、最終の全体整合性・必須テスト・独立レビュー・PDF確認は維持する。検証済みファイルを無断で削除・上書きせず、判定記録を更新する。
- SSH先からMacへ転送した実際の入力と生成物の版を照合する。別環境の同名ファイルや前回の合格を流用しない。
- 出力は変更点、影響対象、再実行するコマンド、再利用可能と判断した根拠、未追跡の範囲。読み取り専用担当は計画・判定のみ返し、ファイルを変更しない。
