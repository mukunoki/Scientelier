# 理解の障害を見つける独立レビュー

担当範囲・読取専用権限と通常の結果提出形式を守る。新しい完了プロトコルは作らない。

1. 読者役はlessonの既知知識だけを前提とし、教材を順に読む。先のページ・作者の解説・他者のレビュー結論を先に見て欠落を埋めない。章ごとの理解問題に、そこまでの教材から答えられるか試す。
2. 原典検証者は主張・数式・比較条件・限界を一次資料に戻って独立に確認する。読者役のわかりやすさ評価だけで正しいとはしない。図解検証者は本文との対応・段階間の変化・ラベル・単位・比喩の限界を見る。
3. 各指摘にフレームID/ページ、足りない前提、起きる誤解、根拠、具体的な改善案を付ける。事実誤り、理解を妨げる飛躍、任意の好みを区別する。
4. 初回判定の提出後、異なるモデル系統が争点を照合する。多数決で指摘を消さず、原典と教材に戻って解消する。別CLIが同系統モデルの場合を独立な異種AIと数えない。
5. 改善後は該当箇所と、その前提/後続の説明を再評価する。同じ図を使う全箇所や数値依存箇所も確認する。不要な全量読み直しは避けるが、最終PDFは全ページを見る。

重要な誤りや理解障害が残れば通常のconcernsとして差し戻す。無制限の美化・同義語置換で反復しない。一次資料取得不能・予算/試行上限に達した場合は成果と具体的な未確認項目を保持する。AIの読者シミュレーションは、人間が理解したという実測ではない。
